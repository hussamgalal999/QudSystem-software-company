# Dual-Agent Coordination Protocol (Qoder ↔ GitHub Copilot)

Version: **1** · Board schema: **1** · Root: `C:\Users\Hossam Galal\Desktop\Qudron\.agent-coordination`

This directory is the **only** shared surface between the two agents. Qoder works in the
main worktree, GitHub Copilot works in one or more separate worktrees, therefore no
agent may rely on seeing the other's working files. Everything that must be agreed is
written here, and every write goes through `coord.py`.

## 1. Invariants

| # | Invariant |
| --- | --- |
| I1 | `events.jsonl` is the single source of truth. Never edit it by hand. |
| I2 | The log is append-only and hash-chained; `verify` must stay green. |
| I3 | Every repository file edit is preceded by a granted reservation **and** a plan ACKed by the peer. |
| I4 | An agent never edits a path reserved by the peer, and never edits the peer's worktree. |
| I5 | Nothing inside `.agent-coordination` is committed or pushed by either agent. |
| I6 | A CLI process holds the board lock for the duration of one mutation only. |

## 2. Layout

```
.agent-coordination/
  coord.py              # the only writer of board state (Python stdlib only)
  PROTOCOL.md           # this file
  README.md             # short runbook + paste-ready activation message
  events.jsonl          # append-only, hash-chained event log (source of truth)
  board/BOARD.md        # rendered snapshot (derived, regenerated by `board --write`)
  board/HEAD.json       # anchored {seq, hash} of the newest event (tamper anchor)
  locks/board.lock      # cross-process lock file (1 byte region lock)
  tests/test_coord.py   # focused, isolated tests
```

`board/BOARD.md` is a convenience rendering. If it disagrees with the log, the log wins —
regenerate with `python coord.py board --write`.

## 3. Event record

One JSON object per line, UTF-8, keys sorted, fields:

| Field | Meaning |
| --- | --- |
| `schema_version` | board schema, currently `1` |
| `seq` | strictly increasing integer starting at 1 |
| `event_id` | `evt-000001` |
| `type` | event type (see below) |
| `agent` | agent that produced the event |
| `ts` | UTC timestamp `YYYY-MM-DDTHH:MM:SS.ffffffZ` |
| `payload` | event-specific body |
| `prev_hash` | `hash` of the previous record, `sha256:000…0` for the first |
| `hash` | `sha256:` + SHA-256 over the canonical JSON of the record **without** `hash` |

Event types: `board.initialized`, `agent.registered`, `agent.heartbeat`,
`plan.proposed`, `plan.acknowledged`, `plan.rejected`, `message.sent`,
`message.acknowledged`, `reservation.granted`, `reservation.denied`,
`reservation.released`, `reservation.renewed`, `status.updated`,
`handoff.submitted`, `handoff.acknowledged`.

`python coord.py verify` re-computes the whole chain and reports `SEQ_GAP`,
`LINK_BROKEN` or `HASH_MISMATCH` with the offending index. It then cross-checks
`board/HEAD.json`, the anchored `{seq, hash}` of the newest event, which catches
edits the pure chain cannot see:

| Code | Severity | Meaning |
| --- | --- | --- |
| `HEAD_ANCHOR_MISSING` | error | anchor file deleted; truncation is no longer detectable |
| `TAIL_TRUNCATED` | error | the log is shorter than the anchor says |
| `ANCHOR_MISMATCH` | error | the anchored event was rewritten |
| `HEAD_ANCHOR_BEHIND` | warning | crash between the append and the anchor write; the chain itself is intact |

Warnings do not fail the command. Exit code `4` means the log is not trustworthy: stop
editing and report it.

## 4. Concurrency and atomicity

* **Lock**: `locks/board.lock`, one byte, `msvcrt.locking(LK_NBLCK)` on Windows and
  `fcntl.flock` elsewhere, retried for up to 20 s. A timeout returns exit code `3`
  (`LOCK_TIMEOUT`); retry, do not force.
* **Append**: inside the lock the process reads the log tail, derives `seq` and
  `prev_hash`, then appends one line with a single `os.write` on a descriptor opened
  `O_APPEND|O_CREAT|O_BINARY`, followed by `os.fsync`. No read-modify-write of
  existing lines ever happens, so concurrent agents cannot lose records.
* **Derived files** (`board/BOARD.md`) are written to a temp file in the same
  directory, fsynced, then swapped with `os.replace` — never partially visible.
* **Trade-off**: each mutation re-reads the log (O(n) in events). Acceptable for a
  board that stays in the hundreds/thousands of events; it removes an entire class of
  cache-coherency bugs.

## 5. Identity

Registration is mandatory before any other action.

```bat
python "C:\Users\Hossam Galal\Desktop\Qudron\.agent-coordination\coord.py" register ^
  --agent copilot ^
  --display-name "GitHub Copilot" ^
  --model "<model you are running>" ^
  --role "<your task role>" ^
  --branch "<git branch of your worktree>" ^
  --worktree "<absolute worktree path>" ^
  --base-sha "<git rev-parse HEAD>"
```

`--branch`, `--worktree` and `--base-sha` are auto-detected with `git` when omitted
(pass `--no-auto-git` to forbid detection). Missing values raise `MISSING_IDENTITY`.
Re-registering the same `--agent` bumps `revision` and refreshes liveness; it is not a
new identity.

Agent ids match `^[a-z0-9][a-z0-9._-]{1,39}$`. This board reserves `qoder` and
`copilot`.

## 6. Workflow (the only acceptable order)

1. `board` — read the live board before doing anything.
2. `register` — publish identity, branch, worktree, base SHA.
3. `msg send` — introduce yourself to the peer with your plan/scope (ACK required).
4. `plan propose` — publish a plan with an explicit task split, owner per task, and the
   files each task touches. Declare `--scope` paths and `--symbols` too: the gate refuses
   edits that the plan does not cover, so an unscoped plan is unusable by design.
5. Peer runs `plan ack --agent <peer> --plan P-000n`. Self-ACK is rejected
   (`SELF_ACK_FORBIDDEN`). A rejection (`plan reject`) blocks the plan until superseded
   by a new proposal.
6. `reserve` — take a lease on the exact paths and symbols you are about to touch.
7. `gate --agent … --plan P-000n --files …` — must print `ALLOW` (exit `0`) before the
   first edit.
8. Edit, then `status set` (`waiting_ack`, `in_progress`, `blocked`, `done`).
9. `handoff` — publish what changed, which tests ran, what remains.
10. `release` — free reservations you no longer need (or let the TTL expire).

`status set --state done|handed_off` and `handoff` update the owning task in the plan.

## 7. Messages

`msg send --from <a> --to <b|all> --subject <s> --body <text>` creates `M-000n`.
Default `requires_ack=true`. Recipients see it via `msg inbox --agent <b>` (ACK-required
and not yet acknowledged) or `--all`. `msg ack --agent <b> --message M-000n` clears it.
Only the recipient can ACK (`NOT_A_RECIPIENT`). Agents may not message themselves.

Messages are the correct channel for: scope changes, blockers, "I need this path",
contradictory base SHAs, and delivery notifications.

## 8. Reservations

```bat
python coord.py reserve --agent qoder --plan P-0001 ^
  --files src/app.py src/lib/ --symbols "Order.total,OrderService.apply" --ttl-minutes 120
```

* Paths are **canonicalised**: POSIX separators, lower case (Windows is case-insensitive),
  empty and `.` segments dropped, `..` resolved. `src/../file.py` therefore becomes
  `file.py` and collides with `file.py` instead of aliasing past it. A path that escapes
  the repository root (`PATH_ESCAPES_ROOT`) or resolves outside it (`PATH_OUTSIDE_REPO`)
  is rejected; an absolute path is required to pass `--repo-root`
  (`PATH_REQUIRES_REPO_ROOT`) and is then made relative, so both worktrees reason about
  the same string.
* **Path conflict**: identical paths, or one is a directory prefix of the other
  (`a/b` vs `a/b/c`, and `.` covers everything).
* **Symbol conflict**: identical symbols, or one is a dotted prefix of the other
  (`order.total` vs `order.total.compute`).
* Same path set + same symbol set reserved again by the same agent = `reservation.renewed`
  (lease extension), never a conflict.
* Conflicting request → `reservation.denied` is logged (audit) and the command exits `3`
  printing every conflicting reservation, its holder and expiry. The requester must
  message the holder or wait for the TTL.
* Reservations expire after the TTL (`--ttl-minutes`, default 120). Expired reservations
  no longer block anyone but remain in the log; `renew` is only valid while active.
* Only the owner may `release` or `renew` (`NOT_RESERVATION_OWNER`).

## 9. Pre-edit gate

`gate` is the contract enforcement point. It is advisory to the operating system but
binding on the agents: **no edit without `ALLOW`**. A **specific, fully acknowledged
plan is mandatory** (there is no "no plan" path), and that plan must also *cover* the
requested paths and symbols — proposing a plan and ACKing it is not enough on its own.

Path coverage = plan `--scope` entries plus the `files` of tasks owned by the caller
(owner = caller, `both` or `any`), compared with the same prefix rule used by
reservations. Symbol coverage = plan `--symbols`.

Checks, in order:

| Code | Severity | Meaning |
| --- | --- | --- |
| `AGENT_NOT_REGISTERED` | block | register first |
| `BASE_SHA_DIVERGED` | warning | your base SHA differs from the peer's; re-sync or note it |
| `PLAN_REQUIRED` | block | no `--plan` given; a specific acknowledged plan is required |
| `PLAN_NOT_FOUND` | block | plan id does not exist |
| `PLAN_REJECTED` | block | peer rejected this plan |
| `PLAN_NOT_ACKED` | block | lists who still has to ACK (and the exact command) |
| `PLAN_SCOPE_UNDECLARED` | block | the plan declares no scope and no task files for you |
| `PLAN_SCOPE_MISMATCH` | block | a requested path or symbol is outside the plan's coverage |
| `PLAN_SYMBOLS_UNDECLARED` | warning | the plan declares no `--symbols`; symbol edits then rely on reservations alone |
| `NOT_RESERVED` | block | no active reservation of yours covers this path or symbol |
| `RESERVATION_EXPIRED` | block | your reservation lapsed; renew it |
| `RESERVED_BY_PEER` | block | peer holds an overlapping path or symbol reservation |
| `PEER_REQUIRED` | block | peer must be registered before operations can proceed |
| `BOOTSTRAP_EXEMPTION_DENIED` | block | bootstrap exemption is denied or expired |
| `SOLO_BOOTSTRAP_EXEMPTION` | warning | solo bootstrap exemption is active but strictly bounded |
| `LOG_MISSING` | block | event log file is missing or uninitialized |
| `BOARD_CORRUPT` | block | event log hash chain or anchor is corrupt |
| `TASK_REFERENCE_AMBIGUOUS` | block | task reference matches multiple tasks across plans |
| `PATH_INVALID_COMPONENT` | block | path contains invalid or unsafe components |
| `PATH_ADS_FORBIDDEN` | block | NTFS Alternate Data Streams (colons in paths) are forbidden |
| `PATH_DRIVE_RELATIVE` | block | drive-relative paths (e.g. C:foo) are forbidden |

Paths **and** symbols are checked identically for reservation coverage, ownership,
expiry and peer conflicts — a symbol-only edit cannot bypass the gate.

Exit codes: `0` = `ALLOW`, `3` = `BLOCK` (or lock timeout, or reservation denied),
`2` = usage error, `4` = corrupted log. `--allow-solo` only suppresses `PLAN_REQUIRED`
and `PLAN_NOT_ACKED` while **no peer is registered** (bootstrap of this directory); it
never bypasses plan-scope coverage or a reservation check. `--strict` is accepted for
compatibility but no longer changes behaviour: the strict rules above always apply.

## 10. Progress and hand-off

States: `idle`, `planning`, `waiting_ack`, `in_progress`, `blocked`, `paused`, `done`,
`handed_off`.

A hand-off record contains: `handoff_id`, agent, `plan_id`, `task_id`, `summary`,
`files`, `tests` (what actually ran and its result) and `next_steps`. Hand-offs are the
handover artefact between worktrees; the peer acknowledges by `msg ack` or by continuing
work in a new plan.

## 11. Failure handling

| Symptom | Correct response |
| --- | --- |
| `LOCK_TIMEOUT` (exit 3) | retry after a short pause; if it persists, `msg send` to the holder and stop |
| `verify` not OK (exit 4) | stop editing, do not "fix" the log, report to the user and the peer |
| `BASE_SHA_DIVERGED` warning | note the divergence in a message; rebase/merge only inside your own worktree |
| Reservation held by peer and needed now | `msg send` with `--plan`, wait for release/expiry, or narrow your scope to unreserved paths |
| Peer never answers | keep `status set --state blocked --note "waiting ACK from <peer>"`; do not edit |

## 12. Non-goals

* No network transport, no daemon, no background process — one CLI call per mutation.
* No automatic merge of worktrees, no commit, no push.
* No secret storage: everything written here is readable by both agents and by humans.
* No enforcement against an agent that ignores the protocol; the gate is a discipline
  contract plus an audit trail, not a sandbox.
